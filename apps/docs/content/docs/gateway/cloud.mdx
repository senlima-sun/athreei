# Cloud Gateway

The cloud gateway is a hosted service that exposes MCP tools via Server-Sent Events (SSE) transport. This allows web-based AI applications to access browser tools without running local binaries.

## Overview

```
┌───────────────────┐         ┌──────────────────┐
│  Web AI App       │   SSE   │  athreei Cloud   │
│  (Browser)        │ ◄─────► │  Gateway         │
└───────────────────┘         └────────┬─────────┘
                                       │
                              ┌────────┴─────────┐
                              │  MCP Servers     │
                              │  (per session)   │
                              └──────────────────┘
```

Each SSE connection creates a new session with its own gateway instance and connected MCP servers.

## Endpoints

### Root

```
GET /
```

Returns service information:

```json
{
  "name": "athreei-gateway-cloud",
  "version": "0.1.0",
  "description": "Cloud-hosted MCP gateway with SSE transport",
  "endpoints": {
    "health": "/health",
    "sse": "/mcp/:endpointName/sse",
    "messages": "/mcp/messages"
  }
}
```

### Health Check

```
GET /health
```

Returns service health status.

### SSE Connection

```
GET /mcp/:endpointName/sse
```

Establishes an SSE connection for MCP communication.

**Headers:**

- `Authorization: Bearer <API_KEY>` - Required API key for authentication

**Parameters:**

- `endpointName` - Identifier for the endpoint configuration

**Response:** Server-Sent Events stream

### Messages

```
POST /mcp/messages?sessionId=<SESSION_ID>
```

Send MCP messages (tool calls, etc.) to the gateway.

**Query Parameters:**

- `sessionId` - Session ID received from the SSE endpoint event

### Session Resume

```
GET /mcp/session/:sessionId/sse
```

Resume an existing session via SSE without creating a new one.

## Connecting from Web Apps

### Basic SSE Connection

```javascript
// Note: EventSource doesn't support custom headers, use fetch for SSE with auth
const API_KEY = "your-api-key"
const ENDPOINT = "your-endpoint-name"

const response = await fetch(
  `https://gateway.athreei.com/mcp/${ENDPOINT}/sse`,
  {
    headers: {
      Authorization: `Bearer ${API_KEY}`,
    },
  }
)

const reader = response.body.getReader()
const decoder = new TextDecoder()

let sessionId = null

while (true) {
  const { done, value } = await reader.read()
  if (done) break

  const chunk = decoder.decode(value)
  // Parse SSE events to get sessionId from "endpoint" event
  if (chunk.includes("event: endpoint")) {
    const match = chunk.match(/data: \/mcp\/messages\?sessionId=([^\n]+)/)
    if (match) sessionId = match[1]
  }
}
```

### Calling Tools

```javascript
async function callTool(sessionId, name, args) {
  const response = await fetch(
    `https://gateway.athreei.com/mcp/messages?sessionId=${sessionId}`,
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        jsonrpc: "2.0",
        method: "tools/call",
        params: { name, arguments: args },
        id: Date.now(),
      }),
    }
  )

  return response.json()
}

// Example: Get page content
const result = await callTool(sessionId, "browser__get_content", {
  format: "markdown",
})
```

## Session Management

The cloud gateway automatically manages sessions:

- **Session Creation** - New session created on SSE connection
- **Idle Timeout** - Sessions closed after period of inactivity
- **Cleanup** - Resources freed when session ends

### Session Lifecycle

1. Client establishes SSE connection
2. Gateway creates session with unique ID
3. MCP servers spawned for the session
4. Tools available via the session
5. Session cleaned up on disconnect or timeout

## Environment Variables

| Variable          | Default                 | Description                                |
| ----------------- | ----------------------- | ------------------------------------------ |
| `PORT`            | `3001`                  | Port to listen on                          |
| `PLATFORM_URL`    | `http://localhost:3000` | Platform API URL for config and validation |
| `NODE_ENV`        | `development`           | Environment mode (development/production)  |
| `ALLOWED_ORIGINS` | (all in dev)            | Comma-separated allowed CORS origins       |

## Self-Hosting

You can deploy the cloud gateway yourself:

### Using Docker

```dockerfile
FROM oven/bun:1
WORKDIR /app
COPY packages/gateway-cloud ./
RUN bun install
EXPOSE 3001
CMD ["bun", "run", "src/index.ts"]
```

### Using Fly.io

A `fly.toml` configuration is included in the repository:

```bash
cd packages/gateway-cloud
fly deploy
```

### Environment Setup

Required environment variables for production:

```bash
PORT=3001
NODE_ENV=production
ALLOWED_ORIGINS=https://your-app.com
```

## Security Considerations

<Callout type="warning">
  The cloud gateway processes browser automation commands. Consider these
  security practices:
</Callout>

1. **Origin Restrictions** - Set `ALLOWED_ORIGINS` to limit which domains can connect
2. **Authentication** - Implement authentication before production use
3. **Rate Limiting** - Add rate limiting to prevent abuse
4. **Audit Logging** - Enable logging for security audits

## Comparison with Local Gateway

| Aspect        | Cloud Gateway  | Local Gateway   |
| ------------- | -------------- | --------------- |
| Transport     | SSE            | stdio           |
| Setup         | API endpoint   | Binary download |
| Data flow     | Through server | Local only      |
| Session state | Server-managed | N/A             |
| Best for      | Web apps       | Desktop apps    |
